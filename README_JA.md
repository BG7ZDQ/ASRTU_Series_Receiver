# ASRTUシリーズ衛星受信機 1.5

[中文](README.md) · [English](README_EN.md) · **日本語**

ASRTUシリーズ衛星の受信、復調、テレメトリ転送、および自動ドップラー補正を行うC++/Qtスイートです。受信・デコーダー、デスクトップランチャー、Linuxネイティブテレメトリプロキシ、Windows用プロキシラッパー、SDR#用ローカルRAW I/Qブリッジプラグインを含みます。

Contributors: **BG7ZDQ** **BI1NWO** **BG6HNY** **BG4QBF**

## 主な機能

- 共有メモリRAW I/Q、ステレオ・ゼロIF I/Q、モノラル12 kHz実数IF、録音ファイル入力
- BPSK復調、畳み込み符号/Viterbi復号、FECフレーム出力
- リアルタイムのウォーターフォール、スペクトラム、コンステレーション、SNR、RSSI、ループ周波数偏差、同期状態
- WAV自動録音（任意）、完全なフレーム、SVR出力、セッション単位のログ
- 複数TLE取得元、衛星選択、周波数プリセット、SGP4追跡、SDR#自動ドップラー制御
- 地上局のコールサインと位置を設定できるテレメトリアップロードプロキシ
- OSの言語に応じた中国語・日本語・英語の自動切り替え
- フレーム内容、地上局情報、サーバー応答を表示する独立したクロスプラットフォームSatNOGSウィンドウ。録音再生は送信しません

## 使用方法

### 1. インストールと初期設定

1. `ASRTU_Series_Receiver_Setup.exe`を実行し、同梱のSDR#テレメトリプリセットをインストールするか選択します。
2. デスクトップから**ASRTUシリーズ衛星ランチャー**を開きます。
3. コールサイン、経度、緯度、標高を入力します。座標は衛星追跡とドップラー計算に使用され、ローカルに保存されます。
4. 受信系に合う入力を選択します。サウンドカード欄はサウンドカード入力時のみ表示されます。

### 2. 入力モード

| 入力 | 用途 | 信号形式 |
| --- | --- | --- |
| ローカル共有メモリRAW I/Qブリッジ | 同梱SDR#とASRTUプラグイン | SDR#からの複素ゼロIF RAW I/Q |
| ステレオ・ゼロIF RAW I/Q入力 | SDRソフトから仮想サウンドカードへ出力 | 左右チャンネルがI/Q、中心0 Hz |
| モノラル実数12 kHz無線機IF入力 | 無線機、受信機、録音機器の実数IF出力 | 目的信号の中心が+12 kHz |

サウンドカード入力では実際の録音デバイスを選択してください。デバイスを変更または再接続するときは、現在の受信を停止し、デバイスを選び直してから再起動します。

### 3. SDR# RAW I/Qブリッジ

1. **SDR#テレメトリープリセットを開く**をクリックします。
2. SDR#で受信機を選択し、衛星のダウンリンク周波数に合わせて受信を開始します。
3. ASRTUプラグインでローカルRAW I/Qブリッジを有効にします。周波数補正が必要なら自動ドップラーも有効にします。
4. ランチャーで**ローカル共有メモリRAW I/Qブリッジ**を選び、**受信を開始**をクリックします。

SDR#からサンプルが届くまでは`NOSYNC`のままです。SDR#を一時停止または終了した後の古いSNR値を、受信中の信号と判断しないでください。

### 4. サウンドカード入力

ステレオI/Qには2チャンネルのゼロIF RAWデータを出力するデバイスが必要です。通常のスピーカー音声はI/Qではありません。無線機の実数IFではモノラルモードを使用し、音声スペクトラム上で目的信号を12 kHz付近に置きます。実数入力のグラフでは12 kHzを0 Hzとして表示するため、周波数偏差を直接確認できます。

モードとサウンドカードを選択したら**受信を開始**をクリックします。入力を保存する場合は、先に**今回の受信を自動録音**を有効にしてください。

### 5. 受信・復号状態の確認

- 入力ウォーターフォールには、広帯域ノイズだけでなく連続した目的信号が見える必要があります。
- BPSKコンステレーションはI軸の左右2か所に集まります。
- SNRが上昇しループ偏差が安定すれば、キャリアおよびタイミングループが有効範囲に入っています。
- `SYNCED`は最近使用可能なフレームを受信したことを示します。`NOSYNC`は未同期、またはフレームのタイムアウトを示します。
- 実際の復号確認には、ログの`FEC frame`、完全な16進PDU、SVR出力を使用してください。SNRだけでは判断できません。

### 6. テレメトリアップロード

次の2経路は任意で、ローカル復号とは独立しています。

- **アップロードプロキシを起動**：選択した衛星のアップロード経路を開きます。MMTサーバーがある衛星は従来のプロキシを使用します。
- JAMXにはMMT送信先がないため、JAMX選択時はSatNOGSが必須です。ランチャーはクロスプラットフォームの`ASRTU_SatnogsUploader`を起動し、GNU Radio PMT PDUを検証して223バイトのフレームを16進表示し、地上局情報とHTTPS応答を表示します。

コンピューターの時刻、コールサイン、座標を正確にしてください。過去の録音が現在の観測として登録されないよう、ファイル再生中はSatNOGS送信を無効にしています。

### 7. 衛星追跡と自動ドップラー

**衛星追跡・自動ドップラー**をクリックします。設定されたすべてのTLE取得元をダウンロード・統合し、衛星と周波数プリセット、または任意のダウンリンク周波数を選択できます。方位角、仰角、距離、TLEエポックを確認してから、SDR#プラグインの自動ドップラーを有効にしてください。

ドップラー補正は受信周波数を調整するだけで、復号成功を意味しません。最終判断には`SYNCED`、FECフレーム、ログを使用します。

### 8. 録音と再生

- 自動録音はWAVとログを`ASRTU1_Records/<日時>/`へ保存します。Windowsでは既定でインストール先の隣、Linuxでは現在のユーザーデータディレクトリを使用します。
- **録音とログを開く**で保存先を直接開けます。
- **録音ファイルを再生**では対応ファイルを選択できます。モノラルは12 kHz実数IF、ステレオはゼロIF I/Qとして処理します。
- **録音ファイルをクイック再生**は、録音の選択と回帰確認を素早く行う入口です。ライブのサウンドカード入力には切り替わりません。

### 9. トラブルシューティング

- **常にNOSYNC：** 衛星の可視時間、周波数とドップラー、入力モード、ウォーターフォール上の信号を確認してください。
- **スペクトラムの鏡像や折り返し：** モノラル実数IFをステレオI/Qとして選んでいないか、I/Qチャンネルが逆でないか確認します。
- **起動後にサンプルがない：** 共有メモリではSDR#の受信とブリッジが有効か確認します。サウンドカードでは現在存在する入力デバイスを選び直します。
- **SNRはあるがフレームがない：** コンステレーション、ループ偏差、FECログを確認します。キャリアの存在だけではフレーム同期や誤り訂正の成功を保証しません。
- **アップロードしない：** SatNOGSを選択せず、アップロードプロキシも起動しないでください。

## リポジトリ構成

- `apps/` — DSP受信機、ランチャー、ドップラー画面、Linuxネイティブプロキシ、Windows用プロキシラッパー
- `libs/` — 復調/FECパイプラインと共通コード
- `plugins/` — SDR#ローカルRAW I/Q・ドップラーブリッジ
- `assets/` — ブランド画像、アイコン、UI素材、翻訳
- `third_party/` — 上流ライセンスを保持する第三者ソース
- `packaging/inno/` — Inno Setupスクリプト
- `packaging/payload/` — 完全版インストーラー用の統合ランタイム
- `tests/` — DSPベンチマークと回帰テスト入口
- `tools/` — 翻訳・アセット保守スクリプト
- `docs/` — アーキテクチャ、ビルド、翻訳、リリース文書

## ビルド

Visual Studio 2022 Build ToolsとInno Setup 6があれば、リポジトリのルートから完全なインストーラーを作成できます：

```powershell
.\build_installer.ps1
```

同梱ポータブル版ではなくDSPを再コンパイルする場合は
`.\packaging\inno\build_installer.ps1 -RebuildDsp`を使用し、radioconda/GNU Radio開発環境も用意してください。

完全な環境、Linux/macOSの現状、依存関係は[docs/BUILDING.md](docs/BUILDING.md)を、インストーラー作成は[docs/PACKAGING.md](docs/PACKAGING.md)を参照してください。
